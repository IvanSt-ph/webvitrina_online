# Импорт характеристик категорий — MVP

Страница: `/admin/attribute-import`, также ссылка «Импорт характеристик» на странице категорий. Доступ: авторизованный администратор с подтверждённой почтой, существующие middleware проекта и CSRF. Новые зависимости, миграции и права отдельного уровня не добавляются.

## Использование

1. Скачайте шаблон на странице импорта или используйте `docs/templates/category-attributes.xlsx`.
2. Замените демонстрационную строку своими данными. Не импортируйте пример как реальные характеристики.
3. Сохраните один лист XLSX с заголовками A:H в точном порядке:
   `category_slug`, `group_name`, `attribute_name`, `type`, `unit`, `is_filterable`, `options`, `sort_order`.
4. Загрузите файл кнопкой «Предварительная проверка». Проверьте все строки, счётчики и причины ошибок. Фильтр позволяет выбрать статус.
5. При любой строке INVALID, UNSUPPORTED или CONFLICT весь импорт блокируется. Исправьте файл и повторите проверку.
6. Повторно выберите **тот же файл**, отметьте подтверждение и нажмите «Применить импорт». Срок подтверждения — 30 минут. Файл не сохраняется приложением: используются временные загрузки PHP и подписанное шифрованием подтверждение с SHA-256 файла, снимком плана и ID администратора.
7. Если изменился файл или состояние каталога, получите новый предпросмотр и подтвердите его. Повторный импорт после нового предпросмотра не добавляет дубликатов.

## Контракт данных

- Все восемь заголовков обязательны. Пустые строки пропускаются, номера ошибок соответствуют строкам Excel.
- `category_slug`: точный существующий slug конечной категории, до 255 символов. Не используются ID из экспорта.
- `group_name`: необязательный текст до 255 символов, только для отчёта.
- `attribute_name`: непустой текст до 255 символов.
- `type`: строго `text`, `number`, `select`. Цвета, boolean и multiselect не импортируются.
- `unit`: необязательный текст до 50 символов, как в существующей административной валидации.
- `is_filterable`: только `0` или `1`, не «да/нет» и не Excel TRUE/FALSE.
- `options`: для select JSON-массив от 1 до 100 непустых строк, каждый вариант до 255 символов. Например `["S","M","L"]`. Порядок вариантов значим. В остальных типах ячейка должна быть пустой.
- `sort_order`: целое число 0–4294967295. Применяется только к новой привязке; существующий порядок сохраняется.
- Пробелы по краям, управляющие символы и похожие варианты выбора не исправляются автоматически.
- Повтор характеристики с одинаковым нормализованным названием в одной категории Excel блокирует файл как INVALID. Разные определения одного названия в разных категориях разрешены. Нормализация названий игнорирует регистр и повторные пробелы; это не лингвистическое сравнение и не объединение синонимов.
- Точное совпадение включает имя, тип, единицу, фильтруемость, порядок options и отсутствие цветов. Точная существующая привязка даёт UNCHANGED; точное определение без привязки — ADD_LINK. Если точного определения нет, допускается CREATE_AND_LINK, даже когда в других категориях существуют иные определения того же названия.
- CONFLICT возникает, если в текущей категории привязано отличающееся определение того же нормализованного названия, определение с цветами либо несколько одноимённых определений (даже при наличии точного совпадения). Такие случаи требуют ручного решения.

## Ограничения XLSX

Это парсер ограниченного шаблона, а не универсальный Excel-конвертер. До 2 МиБ файла, 5000 строк данных, 20 частей ZIP, 8 МиБ на часть, 12 МиБ суммарно, коэффициент сжатия не более 200. До 10000 символов на ячейку. Архив не извлекается на диск, имена частей проходят разрешающий список. XML обрабатывается без сети, DTD/ENTITY запрещены. Формулы, внешние ссылки, гиперссылки, макросы, дополнительные листы, объединённые ячейки, форматированный текст и нестандартные связи отклоняются. Читаются обычные inline/shared strings и числовые ячейки без преобразования форматирования и вычисления формул.

Если редактор сохраняет XLSX со структурой вне этого контракта, файл будет отклонён. Не расширять парсер до универсального самостоятельно: согласовать библиотеку или отдельное преобразование. Реальный пользовательский Excel ещё не предоставлен; проверены созданный шаблон и тестовые книги.

## Безопасность применения

`config/attribute_import.php` задаёт `allowed_database` через серверную переменную `ATTRIBUTE_IMPORT_ALLOWED_DATABASE`; значение по умолчанию — `webv3_attributes_test`. Отсутствующий ключ конфигурации, пустое значение, ошибка определения БД или несовпадение имени запрещают применение. Для будущего production-импорта администратор должен явно настроить разрешённое имя на уровне развёртывания; HTTP-параметры настройку не изменяют. Рабочую `.env` для текущего тестового импорта менять не нужно.

`ImportDatabaseGuard` выполняет `SELECT DATABASE()` через write-PDO стандартного подключения и подключений моделей; также проверяет SQL-подключения кеша, limiter, блокировок кеша и сессий. Проверка вызывается перед транзакцией apply и повторно внутри неё до блокировок/вставок. Middleware `GuardAttributeImportDatabase` предваряет web-сессии и throttle на обоих POST-маршрутах preview/apply, чтобы при неверной БД не записывались даже HTTP-счётчики. Отказ возвращает понятный текст и HTTP 503 без рендеринга сессии/Blade. Остальные маршруты не затрагиваются; проверки прав, CSRF, файла, подтверждения и плана сохранены.

Если старый конфигурационный кеш не содержит нового ключа, импорт безопасно заблокируется. Его обновление — отдельная операция развёртывания; добавление защиты не очищает и не перестраивает кеш автоматически. При обычном `artisan serve` без кеша конфигурации новый код используется следующими запросами; перезапуск нужен для изменения переменных окружения процесса либо при отключённой перепроверке файлов OPcache/долгоживущих workers. При перезапуске обязательно сохранить временное подключение к тестовой БД.

Предпросмотр импортёра выполняет только чтение БД; обычные механизмы HTTP сессии, кеша административного layout и ограничения частоты запросов продолжают работать как в проекте. Импортёр не сохраняет файл и план в БД.

Применение повторно читает XLSX, проверяет подтверждение, получает существующую общую блокировку `AttributeDefinitionService::lock()`, затем блокирует строки категорий, определений и привязок и перестраивает план внутри транзакции. Снимок консервативно охватывает весь каталог, поэтому даже несвязанное изменение категории/определения/привязки может потребовать нового подтверждения. Блокировки широкие; MVP рассчитан на небольшие административные пакеты и согласованные с существующим механизмом блокировок записи.

Записываются только новые `attributes` и `attribute_category`. Не вызываются detach, архивирование или изменение существующих определений, связей и `attribute_values`. При ошибке записи транзакция откатывается полностью. После коммита очищается кеш фильтров затронутых категорий и родителей и обновляется версия кеша каталога. Журнал содержит только итоговые счётчики. Ошибка кеша/журнала после коммита показывается отдельно и не означает отмену уже сохранённых данных.

## Ручная проверка

Проводить на изолированной `webv3_testing`, предварительно проверив фактическое подключение. Не менять рабочую `.env` и не импортировать в `webv3` в рамках проверки разработки.

1. Новая уникальная характеристика → CREATE_AND_LINK; после применения и нового предпросмотра → UNCHANGED.
2. Точное определение из другой категории → ADD_LINK, без второго определения.
3. Неизвестный slug, другой unit/options, multiselect и повтор строки → весь файл заблокирован, указаны строки и причины.
4. После предпросмотра изменить файл → применение отклоняется. Изменить определение/привязку каталога → требуется новый предпросмотр.
5. Сравнить прежние определения, связи, значения товаров и sort_order до и после: они должны совпадать.
6. Проверить доступ продавца/покупателя: 403. Проверить применение без CSRF в обычном HTTP окружении: 419.

## Автотесты

`tests/Unit/ImportDatabaseGuardTest.php` проверяет разрешённую/неверную/неопределённую БД, отсутствие настройки, ошибки соединения, дополнительные подключения и ранний HTTP-отказ на mock-объектах. Не загружает Laravel, `.env` или PDO и не обращается к MySQL:

```powershell
php vendor/phpunit/phpunit/phpunit --no-configuration --bootstrap vendor/autoload.php --do-not-cache-result tests/Unit/ImportDatabaseGuardTest.php
```

Feature-набор ниже после своих проверок `TestDatabaseSafety` явно разрешает только `webv3_testing` для собственного процесса. Его запуск требует отдельно согласованной безопасной БД; для проверки новой защиты он не нужен.

`tests/Unit/CategoryAttributeImportParserTest.php` не использует БД. `tests/Feature/CategoryAttributeImportTest.php` перед записью проверяет конфигурацию и фактические `SELECT DATABASE()`, `CURRENT_USER()` через `TestDatabaseSafety`. Допускаются только `webv3_testing` и `webvitrina_test@localhost` на утверждённом локальном подключении. Тесты работают на существующей схеме, используют транзакции с откатом; без RefreshDatabase, миграций, сидеров и очистки таблиц. Тест кеша отдельно исполняет перехваченный afterCommit callback, не выполняя реальный коммит тестовых данных.

Запуск напрямую, без `composer test` (его script запускает config:clear):

```powershell
php vendor/phpunit/phpunit/phpunit tests/Unit/CategoryAttributeImportParserTest.php tests/Feature/CategoryAttributeImportTest.php
```

## Отдельный будущий этап группировки

Только после отдельного согласования: nullable string `attribute_category.group_name`, `withPivot('sort_order', 'group_name')` в связи `Category::attributes()`, согласование правил обновления групп и Blade-интерфейсов продавца/карточки товара. В MVP такой миграции и группировки нет.
