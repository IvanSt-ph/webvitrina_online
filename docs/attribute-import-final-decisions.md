## 2. Срок годности: 16 строк

### Что удобнее продавцу и что лучше для фильтра

| Модель | Удобство продавца | Фильтрация | Ограничения |
|---|---|---|---|
| text, без единицы | Можно перенести срок и единицу с маркировки без пересчёта | Не включать диапазонный фильтр: «6 месяцев» и «180 суток» не являются автоматически эквивалентными записями | Разные формулировки; нужен пример заполнения и проверка смысла |
| number, единица «сут.» | Удобно, если исходная маркировка уже в сутках и поле означает одну и ту же длительность | Может поддерживать числовой диапазон при одинаковой семантике и условиях | Продавцу приходится переводить часы/месяцы; теряются условия, нельзя автоматически пересчитывать календарные месяцы |
| Длительность + единица + условия, отдельным этапом | Больше элементов формы, но не требуется выдумывать пересчёт | Сравнение возможно после определения правил нормализации и сопоставимости | Нужны проектирование, валидация и интерфейс; один атрибут текущего MVP этого не обеспечивает |

**Рекомендация для текущего MVP:** необязательный text, unit=null, is_filterable=0, options=null. Не требовать от продавца приблизительных дней. Подсказка должна просить перенести срок с маркировки и отдельно указать условия, если они влияют на него. Это рекомендация к будущему интерфейсу, подсказка сейчас не реализуется.

Не смешивать срок годности продукта, срок после вскрытия, дату окончания и остаток срока конкретной партии. Для фильтра «осталось не менее N дней» нужны данные партии и дата отсчёта; общее поле «Срок годности» этого не даёт. Число в Excel само по себе фильтр не включает: в этих строках is_filterable уже равен 0.

**Точное предлагаемое изменение после согласования для всех 16 строк:** только `type: number → text`, `unit: сут. → пусто` в копии XLSX. Имя, category_slug, group_name, sort_order, is_filterable=0 и пустые options сохранить. Это согласование с #286, а не преобразование значений товаров.

## 3. Класс энергопотребления: 9 строк

Во всех девяти категориях существующее #325 — **text, unit=null, is_filterable=0, options=null**. То есть **существующего списка вариантов нет**; это не список A–G с отключённым фильтром. Excel предлагает **select, unit пусто, is_filterable=1, options=[A,B,C,D,E,F,G]**.

Предпочтительная целевая модель — необязательный select с фильтром только для подтверждённой шкалы. Поле «неизвестно» не должно превращаться в выдуманный класс; отсутствие данных не равно классу G. Не объединять старую и новую шкалу в один неразмеченный список и не переводить A+++ в A автоматически.

Официальные примеры ниже относятся к системе маркировки ЕС и используются как подтверждение структуры шкал, а не как заключение о юридических требованиях рынка WebVitrina. Выбор рынка, поколения маркировки и подвидов товаров должен подтвердить владелец проекта.

| 1236 | Мойка и полировка — moyka-i-polirovka (#218); «Форма выпуска» | #470; select; unit=null; фильтр=1; [Жидкость, Спрей, Пена, Паста, Концентрат] | select; unit пусто; фильтр=1; [Спрей, Аэрозоль, Жидкость, Пена, Паста, Крем, Гель, Порошок] | Не принимать список Excel целиком и не просто объединять оба списка. Сохранить прежние данные; целевую модель разделить на форму, упаковку/способ подачи и концентрацию | Пропадает ложный выбор «жидкость или концентрат». Но добавляются поля; потребуется подтверждение соответствий по товару. Старый «Спрей» сам по себе не определяет физическую форму |

### Что сохранить, добавить и разделить

**Тип средства:**

- Сохранить «Автошампунь», «Активная пена», «Полироль», «Воск», «Очиститель», «Обезжириватель», «Другое».
- Добавить «Чернитель шин» и «Антидождь» после подтверждения границ категории. Если они относятся к другой ветке, настроить соответствующий справочник там, а не расширять эту категорию наугад.
- Для многофункционального товара в рамках single-select согласовать правило основного назначения. Не вводить multiselect скрыто через строку с разделителями.

**Форма выпуска — предлагаемая структура, пока только проект:**

| Новый смысловой признак | Предлагаемые значения | Что происходит с прежними значениями | Ограничение переноса |
|---|---|---|---|
| Физическая форма состава | Жидкость, Гель, Крем, Паста, Порошок; «Пена» только после определения, имеется ли в виду состояние состава или результат нанесения | Смысл «Жидкость» и «Паста» сохранить; новые «Крем», «Гель», «Порошок» проверить по ассортименту | Не выводить физическую форму из способа распыления; даже «Пена» может описывать результат использования |
| Тип упаковки / подачи | Например, флакон без распылителя, флакон с помповым распылителем, аэрозольный баллон — список уточнить по товарам | «Аэрозоль» рассматривать здесь. «Спрей» требует уточнения: это способ нанесения, а не гарантированно помповый флакон | Нельзя автоматически сопоставить все записи «Спрей» с помповым распылителем |
| Концентрация / приготовление | Готовое к применению, Концентрат; инструкции разведения отдельным полем при необходимости | Не терять существующий «Концентрат» | Не всем концентратам приписывать одинаковое разведение; способ применения брать из данных товара |

Новые поля — отдельные продуктовые признаки, не переименование для обхода конфликта. При переходе прежние ID и значения должны оставаться прослеживаемыми. Заполнение новых полей нельзя автоматически считать выполненным только по старому значению. Не все три фильтра нужно сразу показывать покупателю: приоритет — назначение средства; полезность формы и концентрации подтвердить ассортиментом и наполненностью.

## 5. Последствия для текущего импорта

1. После отдельного согласования принятие text для 16 сроков годности можно реализовать правкой только копии Excel: точное совпадение с #286, без изменения БД.
2. Для энергоклассов и автохимии целевые select/новые поля могут улучшить UX, но не совпадут с текущими определениями. Существующий импортёр не заменяет привязки и не меняет определения, поэтому одной правки Excel недостаточно для такого перехода.
3. Согласованное временное принятие прежнего text для отдельных энергокатегорий может убрать соответствующий конфликт, но это не реализация качественного фильтра. Согласованное откладывание строки не считать разрешением её модели: вести отдельный список отложенных строк.
4. Не удалять существующие варианты, не объединять определения и не создавать вторую активную одноимённую характеристику в категории. Перед будущим переходом нужен отдельный разрешённый аудит фактических значений/связей и истории целевой базы, правила отображения старых данных и отката.
5. После утверждения модели — отдельная подготовка изменений и повторный предпросмотр. Текущее число конфликтов не изменялось и не проверялось новым запросом к БД в этой задаче.
